# 解答05 サーバー役に反映する

## 手順(server)
```bash
cd ~/git-practice/server
git status --short
git branch --show-current
git pull --ff-only
git log --oneline -4
cat compose.staging.yml
```

| コマンド | 意味 |
| --- | --- |
| `git status --short` | commit されていない変更があるかを表示する |
| `git pull --ff-only` | GitHub の変更を取り込む。そのまま足すだけで済むときだけ取り込む |
| `git log --oneline -4` | 最近の commit を4つ表示する |

期待結果：
- `git status --short` で何も表示されない
- ブランチの名前が `staging`
- `git pull` で `Fast-forward` と表示され、変更の一覧に `compose.staging.yml | 1 +` が出る
- ファイルの中身が `services:` と `  trivy:` の2行

## 問いの答え
- A1. 自分の側に独自の commit がなく、相手の commit をそのまま後ろに足すだけで済む取り込み方。ブランチの先頭を前へ進めるだけで、マージの commit は作られない
- A2. 自分の側にも、相手にはない commit があるとき(履歴が分かれているとき)。付けないと git が自動でマージの commit を作り、GitHub にはない状態がサーバーにできる。付けておけば、サーバーが GitHub とずれていることに、取り込む前に気づける
- A3. サーバー上で直接書き換えられたファイルがあると、取り込みが失敗したり、GitHub にはない変更がサーバーに残ったりする。先にずれがないことを確かめる
