# 解答10 コンフリクトを解消する

## 手順
### 1〜2. 同じ所を変える2つのブランチを作る(pc)
```bash
cd ~/git-practice/pc
git switch develop
git pull
git switch -c feature/conflict-a
echo "  app-a:" >> compose.staging.yml
git commit -am "app-a を追加"
git push -u origin feature/conflict-a
git switch develop
git switch -c feature/conflict-b
echo "  app-b:" >> compose.staging.yml
git commit -am "app-b を追加"
git push -u origin feature/conflict-b
```

| コマンド | 意味 |
| --- | --- |
| `git commit -am "…"` | すでに git が管理しているファイルの変更を、`git add` を省いてまとめて commit する |

2つのブランチはどちらも同じ `develop` から作るので、互いの変更を知らない。

### 3〜4. プルリクエストを作る(GitHub)
1. 「base」を `develop`、「compare」を `feature/conflict-a` にして作り、マージする
2. 「base」を `develop`、「compare」を `feature/conflict-b` にして作る

期待結果： 2.で、作る画面に「Can't automatically merge.」、作ったあとの画面に「This branch has conflicts that must be resolved」と表示される。「Merge pull request」は押せない。

### 5. コンフリクトを解消する(pc)
```bash
git switch feature/conflict-b
git fetch
git merge origin/develop
cat compose.staging.yml
```

| コマンド | 意味 |
| --- | --- |
| `git merge origin/develop` | GitHub の `develop` の内容を、今のブランチに取り込む |

期待結果： `CONFLICT (content): Merge conflict in compose.staging.yml`、`Automatic merge failed; fix conflicts and then commit the result.` と表示され、ファイルの中身が次のようになる。
```
services:
<<<<<<< HEAD
  app-b:
=======
  app-a:
>>>>>>> origin/develop
```

エディタでファイルを開き、印の3行を消して、両方の行を残す。
```bash
vi compose.staging.yml
```
直したあとの中身：
```
services:
  app-a:
  app-b:
```

```bash
git status --short
git add compose.staging.yml
git commit --no-edit
git log --oneline -4
```

| コマンド | 意味 |
| --- | --- |
| `git add …` | コンフリクトを直したファイルを「解決した」として記録する |
| `git commit --no-edit` | マージを完了する commit を、自動で付く説明のまま作る |

期待結果： 直す前の `git status --short` が `UU compose.staging.yml`。commit のあと、`git log` の一番上が `Merge remote-tracking branch 'origin/develop' into feature/conflict-b`。

### 6. push してマージする
```bash
git push
```
GitHub のプルリクエストの画面を開き直す。

期待結果： 「No conflicts with base branch」に変わり、「Merge pull request」を押せる。マージしたあと、`develop` の `compose.staging.yml` が3行になる。

## 問いの答え
- A1. 「This branch has conflicts that must be resolved」。マージのボタンは押せなかった
- A2. `<<<<<<< HEAD` から `=======` までが、自分のブランチの内容。`=======` から `>>>>>>> origin/develop` までが、取り込もうとした相手の内容。この3行の印は git が書き込んだもので、残したまま commit してはいけない
- A3. ファイルを直して印を消し、`git add` してから `git commit` する。`git add` が「このファイルは解決した」という合図になる
- A4. 作業を始める前と、プルリクエストを出す前に、`develop` の最新を取り込む。ブランチを長く置かず、小さい変更で早く取り込む。同じファイルの同じ所をだれが触るかを、先に声を掛け合う
