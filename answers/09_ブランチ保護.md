# 解答09 ブランチ保護

画面の項目名は、GitHub の変更で違っている場合がある。

## 手順
### 1. ルールを作る(GitHub)
1. 「Settings」→「Rules」→「Rulesets」を開く
2. 「New ruleset」→「New branch ruleset」を押す
3. 「Ruleset Name」に `protect-develop` と入れ、「Enforcement status」を「Active」にする
4. 「Target branches」の「Add target」→「Include by pattern」で `develop` を加える
5. 「Branch rules」の「Block force pushes」にチェックが入っていることを確かめる
6. 「Create」を押す

### 2〜3. reset して強制 push する(pc)
```bash
cd ~/git-practice/pc
git switch develop
git pull
git reset --hard <初期状態の commit>
git push --force-with-lease
```
期待結果： push が拒否される(`remote: error: GH013: Repository rule violations found for refs/heads/develop`、`Cannot force-push to this branch`、`! [remote rejected] develop -> develop` のような表示)。GitHub の `develop` は変わらない。

### 4. 自分の develop を元に戻す(pc)
```bash
git reset --hard origin/develop
git status -sb
```
期待結果： `## develop...origin/develop` と表示される(`behind` が付かない)。

### 5. ルールを消す(GitHub)
「Settings」→「Rules」→「Rulesets」で `protect-develop` を開き、「Delete ruleset」を押す。

## 問いの答え
- A1. 拒否された。reset は自分のPCの中では成功するが、その結果を GitHub に送れない
- A2. revert で打ち消す(履歴を書き換えないので、保護されていても通常どおり取り込める)。reset で戻したい場合は、設定を変えられる人に保護を一時的に外してもらうしかない
- A3. 共有のブランチの履歴を、だれかが誤って(または古い状態から)上書きして、ほかの人の commit を消してしまう事故
