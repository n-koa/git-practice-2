# 解答02 表示を読む

## 手順
```bash
cd ~/git-practice/pc
git log --oneline -3
git switch develop
git pull
git switch -c feature/add-trivy
echo "  trivy:" >> compose.staging.yml
git status --short
git diff
git add compose.staging.yml
git status --short
git commit -m "Trivyの定期診断を追加"
git push -u origin feature/add-trivy
```

| コマンド | 意味 |
| --- | --- |
| `git log --oneline -3` | 最近の commit を3つ、1行ずつ表示する |
| `git switch develop` / `git pull` | `develop` に切り替え、GitHub の最新の内容を取り込む |
| `git switch -c feature/add-trivy` | 今の内容から作業用のブランチを作り、切り替える |
| `echo "  trivy:" >> compose.staging.yml` | ファイルの最後に1行追記する(`>>` は追記) |
| `git status --short` | 変更のあるファイルを、状態の印付きで表示する |
| `git diff` | まだ `git add` していない変更の中身を表示する |

期待結果：
- `git diff` の最後が次のようになる
```
@@ -1 +1,2 @@
 services:
+  trivy:
```
- 1回目の `git status --short` が ` M compose.staging.yml`(M の前に空白)、2回目が `M  compose.staging.yml`(M が左端)
- push の表示に `Create a pull request for 'feature/add-trivy' on GitHub by visiting:` と URL が出る

## 問いの答え
- A1. 先頭の英数字は commit の名前(長い名前の先頭7桁ほど)。括弧の中は、その commit を今指しているブランチの一覧。`HEAD -> …` は自分が今いるブランチ、`origin/…` は GitHub にあるブランチ、何も付かないものは自分のPCのブランチ
- A2. `a/` は変更前、`b/` は変更後のファイルを表す目印(そういうフォルダがあるわけではない)。先頭が `+` の行は足された行、`-` の行は消された行、空白の行は変わっていない行
- A3. `git add` の前は右側に `M`(変更したが、commit の対象にしていない)。`git add` の後は左側に `M`(commit の対象に入っている)
- A4. 作業用ブランチは「今いる場所」から作られる。古い `develop` から作ると、ほかの人の変更が入っていない状態から始めることになり、プルリクエストでコンフリクトが起きやすい
