# 解答03 プルリクエストを出して取り込む

## 手順(GitHub)
1. リポジトリのページに出る黄色い帯のうち、`feature/add-trivy` の行の「Compare & pull request」を押す(出ない場合は「Pull requests」→「New pull request」)
2. 「base」を `develop` に変える。「compare」が `feature/add-trivy` であることを確かめる
3. 「Able to merge.」と表示されていることを確かめ、「Create pull request」を押す
4. 「Files changed」のタブを開く
5. 「Conversation」のタブに戻り、「Merge pull request」→「Confirm merge」を押す
6. 「<ユーザー名> merged commit <英数字> into develop」の行の英数字を控える

期待結果：
- 黄色い帯は、最近 push したブランチの数だけ出る。`develop`・`staging` の帯は押さない
- 3.のあと、「<ユーザー名> wants to merge 1 commit into `develop` from `feature/add-trivy`」と「No conflicts with base branch」が表示される
- 4.の変更が `+  trivy:` の1行だけ
- 5.のあと、「Pull request successfully merged and closed」と表示される

## 問いの答え
- A1. `main`(リポジトリの既定のブランチ)。そのまま作ってマージすると、`develop` ではなく `main` に変更が入る
- A2. 作る画面では「Able to merge.」、作ったあとの画面では「No conflicts with base branch」。コンフリクトがあると「Can't automatically merge.」「This branch has conflicts that must be resolved」と表示される
- A3. 2つ増えた。自分が作った「Trivyの定期診断を追加」の commit と、マージしたときに GitHub が作った「Merge pull request #…」の commit。6.で控えたのは後者
- A4. 書いた本人だけでは気づけない誤りを、ほかの人の目で見つけるため。自分でマージできると、だれも見ていない変更が共有のブランチに入る
